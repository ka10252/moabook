# moabook 유저 테스트 질문지 · 관찰 가이드

> 출시 전 사용성 검증용. **사이트/서버에 반영되는 문서가 아니라**, 테스트를 진행·기록할 때 참고하는 스크립트다.
> 목표: (1) 핵심 퍼널(가입→첫 책 등록/첫 요청→채팅)에서 어디서 막히는지, (2) 무엇을 이해 못 하는지, (3) 다시 쓰고·추천할 의향이 있는지.

---

## 0. 테스트 개요

| 항목 | 권장 |
|---|---|
| 대상 | 싱가포르 거주 한인 5~8명 (책 대여/나눔에 관심 있는 사람). 5명이면 사용성 문제 ~85% 발견 |
| 구성 | 신규 유저 위주. 1~2명은 “책 많이 가진 사람”(공급자 관점), 나머지는 “빌리려는 사람”(수요자 관점) |
| 방식 | 1:1, 15~25분. 화면 공유 + **씽크어라우드**(생각을 소리 내어 말하게) |
| 기기 | **본인 실제 폰**으로. iPhone Safari에서 홈스크린 추가까지 시켜보기(PWA 확인) |
| 준비물 | 테스트용 계정 2개(요청↔수락 시연용), 더미 책 몇 권, 기록 시트(아래 템플릿) |
| 진행자 원칙 | 답을 알려주지 말 것. “어떻게 하실 것 같아요?” “지금 무슨 생각 드세요?”만. 3초 침묵 견디기 |

**측정 3종**: ① 과업 성공/실패 ② 소요 시간·이탈 지점 ③ 주관 난이도(1~5).

## 1. 사전 질문 (배경 · 2분)

| # | 질문 | 왜 묻나 |
|---|---|---|
| P1 | 싱가포르에서 한국 책 어떻게 구하세요? (구매/지인/도서관/전자책) | 대안·페인포인트 파악 |
| P2 | 최근 “빌리거나 나누고 싶었던” 책이 있었나요? | 실수요 존재 확인 |
| P3 | 당근·번개장터 같은 중고/공유 앱 써보셨어요? | 멘탈모델 기준점 |
| P4 | 안 읽고 쌓인 책이 몇 권쯤 되세요? | 공급 잠재력 |

## 2. 과업 시나리오 (핵심 — 관찰 중심)

> 각 과업은 **지시만 하고 방법은 알려주지 않는다.** 성공 기준·관찰 포인트를 보며 기록.

| # | 과업 (테스터에게 주는 지시) | 성공 기준 | 관찰 포인트 | 성공? | 소요 | 막힌 지점 |
|---|---|---|---|---|---|---|
| T1 | (로그인 전) “이 앱이 뭐 하는 곳인지 둘러보세요” | 30초 내 “책 빌리고 나누는 곳”이라고 말함 | 첫 화면에서 목적이 읽히나? 게스트로 어디까지 보이나 | | | |
| T2 | “마음에 드는 책을 찾아 빌려/사보세요” | 책 상세→요청까지 도달 | 로그인 유도 시점 자연스러운가, 요청 버튼을 찾나 | | | |
| T3 | “회원가입 해보세요” | 가입+국가선택+(이메일 인증 인지) | 국가 제한 이해? 인증 메일 필요함을 아나 | | | |
| T4 | “가입 후, 아까 그 책 주인과 대화해 요청을 보내세요” | 채팅방에서 요청 메시지 전송 | 요청 카드가 이해되나, 무슨 일이 일어났는지 아나 | | | |
| T5 | (진행자가 수락 시연) “요청이 수락됐어요. 확인해보세요” | 알림/채팅에서 수락 확인 | 벨/채팅 배지를 보나, 다음 할 일을 아나 | | | |
| T6 | “내 책 한 권을 등록해 나눔/대여로 올려보세요” | 책 등록 완료(제목검색·표지·모드) | 제목 검색 자동완성 쓰나, 대여/판매/나눔 차이 이해? | | | |
| T7 | “빌린 책을 반납 처리해보세요” | 반납 요청→완료 경로 진입 | 반납 흐름을 찾나 | | | |
| T8 | “갖고 싶은데 없는 책을 위시리스트에 올려보세요” | 위시 등록 | 좋아요(관심)와 위시 차이를 아나 | | | |
| T9 | “커뮤니티에 들어가 보세요” | 가입/입장, 게시판·책장 인지 | PIN/초대 이해, 커뮤니티 가치 느끼나 | | | |
| T10 | “가상 도서관(캐릭터 공간)에 들어가 캐릭터를 꾸미고, 지금 읽는 책을 지정해보세요” | 캐릭터 저장 + 읽는 책 말풍선 표시 | 재미있어 하나 vs 이질감, 앱 톤과 안 맞다고 느끼나 | | | |
| T11 | “이 앱을 폰 홈 화면에 추가해보세요” | 홈스크린 아이콘 생성 | 방법을 아나(설치 유도 필요?) | | | |
| T12 | (선택) “알림을 텔레그램으로 받도록 연결해보세요” | 텔레그램 연동 완료 | 연동 과정 이해, 왜 필요한지 납득 | | | |

## 3. 과업 직후 질문 (각 과업 끝에 짧게)

- 방금 그거 얼마나 쉬웠나요? (1 매우 어려움 ~ 5 매우 쉬움)
- 막히거나 헷갈린 부분이 있었나요? 어디서요?
- 기대한 대로 동작했나요? 아니면 뭘 기대했나요?

## 4. 기능별 확인 체크리스트 (진행자용 — 실제 작동 & 이해도)

| 영역 | 확인할 것 | OK / 이슈 |
|---|---|---|
| 첫인상 | 5초 안에 “무엇을 하는 앱”인지 전달되나 | |
| 게스트 접근 | 로그인 없이 어디까지 보이나, 로그인 유도가 거슬리지 않나 | |
| 가입/인증 | 국가 제한(SG) 납득, 이메일 인증 대기 이해, 딥링크 복귀 정상 | |
| 책 요청 | 대여/구매/나눔 구분 이해, 요청 카드 의미 전달 | |
| 채팅 | 실시간 도착, 읽음 표시, 미읽음 배지가 맞나 | |
| 책 등록 | 제목 검색 자동완성 유용한가, 표지/가격/모드 헷갈림 없나 | |
| 반납 | 반납 요청→확인 흐름을 스스로 찾나 | |
| 알림 | 벨 숫자 정확한가, 눌렀을 때 올바른 화면으로 가나 | |
| 위시/좋아요 | 둘의 차이를 이해하나 | |
| 커뮤니티 | 가입 방법 명확, 게시판/책장 가치 느끼나 | |
| 가상공간 | 재미 vs 이질감, 로딩/조작 문제 없나 | |
| 빈 상태 | 책 0개/알림 0개 등에서 뭘 해야 할지 안내되나 | |
| 에러 | 잘못된 입력·네트워크 오류 시 메시지가 이해되나 | |

## 5. 사후 설문 (전체 종료 후 · 정량)

### 5-1. 간이 SUS (1 전혀 아니다 ~ 5 매우 그렇다)
1. 이 앱을 자주 쓰고 싶다
2. 불필요하게 복잡했다 (역)
3. 쓰기 쉬웠다
4. 도움 없이도 쓸 수 있을 것 같다
5. 기능들이 잘 어우러져 있다
6. 앞뒤가 안 맞는 부분이 있었다 (역)
7. 대부분의 사람이 금방 익힐 것 같다
8. 쓰기에 번거로웠다 (역)
9. 쓰면서 자신감이 있었다
10. 쓰기 전에 배울 게 많았다 (역)

### 5-2. 핵심 지표
- **추천 의향(NPS)**: 친구에게 추천할 가능성 0~10점, 이유 한 줄
- **재사용 의향**: 다음에 책 빌릴 일 생기면 이걸 쓸까요? (예/아니오/조건부 — 조건은?)
- **첫 행동 의향**: 오늘 이후 실제로 (a) 책을 올리거나 (b) 빌리려 할 것 같나요? 무엇이 있으면 하겠나요?
- **신뢰/안전**: 모르는 이웃과 책 주고받는 게 걱정되나요? 무엇이 있으면 안심되나요? (신고/차단/평점 등)

## 6. 정성 인터뷰 (마무리 · 5분)

- Q1. 오늘 중 **가장 헷갈렸던** 한 가지는?
- Q2. **없어서 아쉬웠던** 기능 하나만 꼽는다면?
- Q3. 이 앱을 **한 문장**으로 친구에게 설명한다면?
- Q4. 가상 도서관(캐릭터)은 필요하다고 느꼈나요, 아니면 없어도 되나요? 솔직하게.
- Q5. 돈을 낸다면 어떤 부분에? (혹은 무료여야 한다면 왜?)
- Q6. 어떤 책이 많으면 이 앱을 쓸 것 같나요? (콘텐츠 임계량)

## 8. 분석 시 볼 것 (테스트 후)

- **과업별 성공률·평균 시간** → 낮은 과업이 최우선 개선 대상
- **공통 이탈 지점**(2명 이상 막힌 곳) → P0
- **멘탈모델 불일치**(좋아요vs위시, 대여vs나눔, 커뮤니티 PIN 등) → 카피/UI 개선
- **가상공간 반응 분포** → 유지/축소/온보딩 뒤로 미루기 판단 근거
- **정량 요약**: SUS 평균(68 이상이면 평균 이상), NPS, 재사용 의향 비율
