# moabook 유저 테스트 질문지 · 관찰 가이드 (v2)

> 출시 전 사용성 검증용. **사이트/서버에 반영되는 문서가 아니라**, 테스트를 진행·기록할 때 참고하는 스크립트다.
> 목표: (1) 핵심 퍼널(가입→**첫 책 등록(=대여 게이트 해제)**→첫 요청→채팅)에서 어디서 막히는지, (2) 무엇을 이해 못 하는지, (3) 다시 쓰고·추천할 의향이 있는지.
>
> ⚠️ **v2 변경 요약**(2026-08-02 기능 개선 반영): 대여하려면 **내 책 1권 등록 필요(상호성 게이트)** · **학교 이메일 인증 배지** · **활동 배지/완료 거래수(신뢰 신호)** · **알림은 텔레그램 우선** · 가상공간은 **커뮤니티 룸 전용**(전역 도서관 제거) · 반납은 **책 주인만 확인** · 가입은 **싱가포르 거주 여부+지역**. NUS 한인 학생 우선 클로즈드 베타.

## 0. 테스트 개요

| 항목 | 권장 |
|---|---|
| 대상 | **NUS 한인 학생 우선** 5~8명(그 외 싱가포르 거주 한인 일부). 5명이면 사용성 문제 ~85% 발견 |
| 구성 | 신규 유저 위주. 1~2명은 “책 많이 가진 사람”(공급자 관점), 나머지는 “빌리려는 사람”(수요자 관점) |
| 방식 | 1:1, 20~30분. 화면 공유 + **씽크어라우드**(생각을 소리 내어 말하게) |
| 기기 | **본인 실제 폰**으로. 알림은 **텔레그램 연동** 우선 시도(홈스크린 추가는 대안으로) |
| 준비물 | 테스트용 계정 2개(요청↔수락 시연용), 더미 책 몇 권(**미리 시딩**), 학교 이메일 접근 가능 여부 확인, 기록 시트 |
| 진행자 원칙 | 답을 알려주지 말 것. “어떻게 하실 것 같아요?” “지금 무슨 생각 드세요?”만. 3초 침묵 견디기 |

**측정 3종**: ① 과업 성공/실패 ② 소요 시간·이탈 지점 ③ 주관 난이도(1~5).

## 1. 사전 질문 (배경 · 2분)

| # | 질문 | 왜 묻나 |
|---|---|---|
| P1 | 싱가포르에서 한국 책 어떻게 구하세요? (구매/지인/도서관/전자책) | 대안·페인포인트 파악 |
| P2 | 최근 “빌리거나 나누고 싶었던” 책이 있었나요? | 실수요 존재 확인 |
| P3 | 당근·번개장터 같은 중고/공유 앱 써보셨어요? | 멘탈모델 기준점 |
| P4 | 안 읽고 쌓인 책이 몇 권쯤 되세요? | 공급 잠재력(=게이트 해제 가능성) |
| P5 | NUS(또는 소속 학교) 이메일 지금 확인 가능하세요? | 학교 인증 과업 가능 여부 |

## 2. 과업 시나리오 (핵심 — 관찰 중심)

> 각 과업은 **지시만 하고 방법은 알려주지 않는다.** 성공 기준·관찰 포인트를 보며 기록.
> 흐름이 바뀌었다: **빌리려면 먼저 내 책을 1권 올려야 한다(상호성 게이트).** 그 반응을 꼭 관찰.

| # | 과업 (테스터에게 주는 지시) | 성공 기준 | 관찰 포인트 | 성공? | 소요 | 막힌 지점 |
|---|---|---|---|---|---|---|
| T1 | (로그인 전) “이 앱이 뭐 하는 곳인지 둘러보세요” | 30초 내 “한국 책을 이웃과 빌리고 나누는 곳”이라고 말함 | 목적이 읽히나? NUS/한인 커뮤니티 느낌 오나? 게스트로 어디까지 보이나 | | | |
| T2 | “마음에 드는 책을 하나 빌려보세요” | 요청 시도 → **대여 게이트("책 1권 등록") 만남** | 게이트가 이해되나? “왜 내 책부터 올려야 하지”에 납득/불만? 등록으로 넘어가나 | | | |
| T3 | “회원가입 해보세요” | 가입 + **싱가포르 거주 여부/지역** 선택 + 이메일 인증 인지 | 거주 질문·지역 선택 이해? 미거주 시 안내 이해? 인증 메일 필요함을 아나 | | | |
| T4 | “빌리려면 내 책이 필요해요. 책 한 권을 등록해보세요” | 책 등록 완료(제목검색·표지·대여/판매/나눔) | 제목 검색 자동완성 쓰나, 대여/판매/나눔 차이 이해? 등록 후 알림 설정 팝업 반응 | | | |
| T5 | “이제 아까 빌리려던 책을 요청해보세요” | 채팅방에서 요청 카드 전송(게이트 해제됨) | 게이트 풀린 걸 인지하나, 요청 카드 의미 전달되나 | | | |
| T6 | (진행자가 수락 시연) “요청이 수락됐어요. 확인해보세요” | 알림/채팅에서 수락 확인 | 벨/채팅 배지를 보나, 다음 할 일을 아나 | | | |
| T7 | (공급자 관점) “빌려준 책을 돌려받았어요. 반납 처리하세요” | **책 주인이** 채팅 대여 카드에서 “반납 확인” | 반납 확인 버튼을 주인만 갖는 걸 자연스러워하나(빌린 사람은 버튼 없음) | | | |
| T8 | “본인이 학생임을 학교 이메일로 인증해보세요” | 학교 이메일 인증 → **학교 배지** 표시 | 인증 진입점 찾나? 코드 메일 도착·입력 순조로운가? (가입을 학교메일로 했으면 자동 배지 인지) | | | |
| T9 | “프로필에서 내 활동 배지와 거래 정보를 살펴보세요” | 활동 배지 진열장(접힘→펼침)·완료 거래수·대표 배지 인지 | 배지가 **동기부여** 되나? 신뢰 신호로 읽히나? 대표 배지 설정 이해? | | | |
| T10 | “갖고 싶은데 없는 책을 위시리스트에 올려보세요” | 위시 등록 | 좋아요(관심)와 위시 차이를 아나 | | | |
| T11 | “커뮤니티에 들어가 보세요” | 초대 링크/비밀번호로 가입·입장, 게시판·책장 인지 | 온보딩 커뮤니티 안내 기억하나? 참여 방법 명확? 가치 느끼나 | | | |
| T12 | “커뮤니티 룸(가상 공간)에 들어가 캐릭터를 꾸미고 돌아다녀 보세요” | 룸 입장 + 캐릭터 저장 + **이동**(탭) + 읽는 책 지정 | 이동 방법 안내가 도움 되나? 재미 vs 이질감? (전역 도서관은 이제 없음) | | | |
| T13 | “대여 요청 같은 알림을 놓치지 않게 설정해보세요” | 알림 설정 진입 → **텔레그램 연동**(우선) 또는 홈화면 추가 | 텔레그램을 1순위로 자연스럽게 고르나? 왜 필요한지 납득? 연동 순조로운가 | | | |

## 3. 과업 직후 질문 (각 과업 끝에 짧게)

- 방금 그거 얼마나 쉬웠나요? (1 매우 어려움 ~ 5 매우 쉬움)
- 막히거나 헷갈린 부분이 있었나요? 어디서요?
- 기대한 대로 동작했나요? 아니면 뭘 기대했나요?
- (T2 전용) “빌리려면 내 책부터 올려야 한다”는 규칙, 어떻게 느끼셨어요? 공정하다/번거롭다?

## 4. 기능별 확인 체크리스트 (진행자용 — 실제 작동 & 이해도)

| 영역 | 확인할 것 | OK / 이슈 |
|---|---|---|
| 첫인상 | 5초 안에 “한국 책 공유(NUS/한인)” 전달되나 | |
| 게스트 접근 | 로그인 없이 어디까지 보이나, 로그인 유도가 거슬리지 않나 | |
| **대여 게이트** | 내 책 0권일 때 요청→“책 1권 등록” 유도가 이해·납득되나 | |
| 가입/인증 | **거주 여부/지역** 납득, 이메일 인증 대기 이해, 딥링크 복귀 정상 | |
| 책 등록 | 제목 검색 자동완성 유용, 대여/판매/나눔 구분, 첫 등록 후 알림 팝업 | |
| 책 요청 | 게이트 해제 후 요청 카드 의미 전달 | |
| 채팅 | 실시간 도착, 읽음 표시, **총 미읽음 실시간** 반영 | |
| 반납 | **주인만 “반납 확인”**이 자연스러운가 | |
| **학교 인증** | 진입점 발견, 코드 메일 도착, 자동 인증(학교메일 가입) 인지 | |
| **활동 배지** | 진열장(접힘/펼침) 이해, 동기부여, 대표 배지 설정, 공개 토글 | |
| **신뢰 신호** | 학교 배지·완료 거래수가 “안심”으로 읽히나 | |
| 알림 | **텔레그램 우선** 안내 자연스러운가, 벨 숫자 정확, 딥링크 정상 | |
| 위시/좋아요 | 둘의 차이를 이해하나 | |
| 커뮤니티 | 온보딩 안내 기억, 초대/PIN 명확, 게시판/책장 가치 | |
| 가상 룸 | **커뮤니티 룸 전용**, 이동 안내 도움, 재미 vs 이질감 | |
| 빈 상태 | 책 0개/검색 0건/알림 0개에서 뭘 해야 할지 안내되나 | |
| 에러 | 잘못된 입력·네트워크 오류 시 메시지가 이해되나 | |

## 5. 사후 설문 (전체 종료 후 · 정량)

### 5-1. 간이 SUS (1 전혀 아니다 ~ 5 매우 그렇다)
1. 이 앱을 자주 쓰고 싶다
2. 불필요하게 복잡했다 (역)
3. 쓰기 쉬웠다
4. 도움 없이도 쓸 수 있을 것 같다
5. 기능들이 잘 어우러져 있다
6. 앞뒤가 안 맞는 부분이 있었다 (역)
7. 대부분의 사람이 금방 익힐 것 같다
8. 쓰기에 번거로웠다 (역)
9. 쓰면서 자신감이 있었다
10. 쓰기 전에 배울 게 많았다 (역)

### 5-2. 핵심 지표
- **추천 의향(NPS)**: 친구에게 추천할 가능성 0~10점, 이유 한 줄
- **재사용 의향**: 다음에 책 빌릴 일 생기면 이걸 쓸까요? (예/아니오/조건부 — 조건은?)
- **첫 행동 의향**: 오늘 이후 실제로 (a) 책을 올리거나 (b) 빌리려 할 것 같나요? 무엇이 있으면 하겠나요?
- **상호성 게이트 수용도**: “빌리려면 내 책 1권 등록” 규칙이 참여를 **막나 vs 공정하게 느끼나**?
- **신뢰/안전**: 모르는 이웃과 책 주고받는 게 걱정되나요? **학교 인증·활동 배지·완료 거래수**가 안심에 도움이 됐나요?

## 6. 정성 인터뷰 (마무리 · 5분)

- Q1. 오늘 중 **가장 헷갈렸던** 한 가지는?
- Q2. **없어서 아쉬웠던** 기능 하나만 꼽는다면?
- Q3. 이 앱을 **한 문장**으로 친구에게 설명한다면?
- Q4. **“빌리려면 내 책부터”** 규칙, 참여를 늘릴까 줄일까?
- Q5. **학교 인증/배지/완료 거래수** 중 신뢰에 가장 도움된 건? 별 도움 안 된 건?
- Q6. 커뮤니티 룸(캐릭터 공간)은 재방문 이유가 되나요, 아니면 한 번 보고 말 건가요?
- Q7. 돈을 낸다면 어떤 부분에? (혹은 무료여야 한다면 왜?)
- Q8. 어떤 책이 많으면 이 앱을 쓸 것 같나요? (콘텐츠 임계량)

## 8. 분석 시 볼 것 (테스트 후)

- **과업별 성공률·평균 시간** → 낮은 과업이 최우선 개선 대상
- **대여 게이트 수용도** → 콜드스타트 전략의 핵심 검증(막으면 완화, 공정하면 유지)
- **학교 인증 완주율** → 메일 도착/입력 마찰 점검(신뢰 신호 핵심)
- **공통 이탈 지점**(2명 이상 막힌 곳) → P0
- **멘탈모델 불일치**(좋아요vs위시, 대여vs나눔, 커뮤니티 참여, 반납 주체 등) → 카피/UI 개선
- **커뮤니티 룸 반응 분포** → 유지/축소/리텐션 기능 판단 근거
- **정량 요약**: SUS 평균(68 이상이면 평균 이상), NPS, 재사용 의향 비율
