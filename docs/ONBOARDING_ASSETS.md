# 온보딩 화면 사진 (public/onboarding/*.webp)

'보는 방식' 단계에 들어가는 **실제 앱 화면 조각** 3장이다.

| 파일 | 담은 것 |
|---|---|
| `view-spine.webp` | 서가 한 칸 — 책등이 꽂힌 한 줄 |
| `view-cover.webp`  | 표지 뷰 한 줄 — 표지 3권 |
| `view-map.webp`    | 지도 뷰 — 역마다 책이 몇 권 있는지 |

## 왜 그림이 아니라 사진인가

처음엔 도형으로 흉내낸 그림을 넣었다. 책등은 그럭저럭 통했지만 **표지 뷰와 지도 뷰가
실제로 어떻게 보이는지는 전혀 전달되지 않았다.** 온보딩의 목적은 "이런 게 있다"가 아니라
"눌러보면 이렇게 된다"를 미리 보여주는 것이라, 실제 화면을 잘라 넣는다.

## 다시 뽑는 방법

디자인이 바뀌면 사진도 같이 갱신해야 한다 (안 하면 앱과 어긋난 채로 남는다).

1. `npm run dev` 로 띄우고 책이 여러 권 있는 계정으로 로그인
2. Playwright 로 `deviceScaleFactor: 2`, 뷰포트 420×900 에서 각 뷰를 열고
   **가로로 길게**(약 338×172 CSS px) 잘라 PNG 로 저장
3. WebP 로 줄인다 — 폭 640, quality 80. 세 장 합쳐 **64KB** 정도가 목표다
   (PNG 그대로면 700KB가 넘어 온보딩 첫 화면이 느려진다)

```python
from PIL import Image
im = Image.open('shot.png').convert('RGB')
im = im.resize((640, round(im.height * 640 / im.width)), Image.LANCZOS)
im.save('public/onboarding/view-cover.webp', 'WEBP', quality=80, method=6)
```

## 사진에 담지 말 것

- **다른 유저의 닉네임·프로필 사진.** 책등 뷰의 리본에는 빌려준/빌린 사람 이름칩이 붙는다.
  이름칩이 없는 선반 줄을 골라 잘랐다.
- 하단 탭바·플로팅 버튼. 화면 중간으로 스크롤해서 잘라야 안 걸린다.

## 카드 높이

'보는 방식'은 사진 3장이라 온보딩 카드 중 가장 길다(약 740px). 그래서 카드는
**내용만 스크롤하고 진행 버튼은 고정**한다 — 예전엔 카드 전체가 스크롤돼서
iPhone SE(667px)에서 '다음' 버튼이 아래로 밀려 찾아야 했다.
사진을 더 넣으면 `npm run smoke` 로는 안 잡히니, 작은 뷰포트에서 버튼이 보이는지 직접 볼 것.
