# moabook 브랜드 & 디자인 가이드

> **버전**: v2.0 — **Bookshelf Refresh** 적용
> **작성일**: 2026-07-14
> **관련 문서**: [PRD.md](./PRD.md) · [핸드오프 원본](./docs/design/bookshelf-refresh-handoff.md) · [디자인 레퍼런스 HTML](./docs/design/bookshelf-refresh.dc.html)
> **소스 오브 트루스**: `src/index.css` (CSS 변수) · `tailwind.config.ts` (토큰 매핑)

> **v1.0에서 무엇이 바뀌었나**
> 브랜드 무드가 *"Cozy Library(아늑한 서재)"* 에서 **"Editorial Minimal + Virtual Library(에디토리얼 미니멀 + 가상 도서관)"** 로 이동했다.
> 가장 큰 변화는 **포인트 컬러가 월넛 갈색(#7B4B26) → 선셋 코랄(#F26A4B)** 로 완전히 바뀐 것이다. 더 젊고 감각적인 톤을 노린다.

## 1. 브랜드 개요

### 1.1 브랜드 정체성
**MOA (모아북)** — *"우리 동네의 책장을 하나로 모은다"*

### 1.2 브랜드 무드
> **에디토리얼 미니멀 + 가상 도서관.**
> 잡지처럼 절제된 여백과 세리프 헤드라인 위에, 실제 서가에 들어선 듯한 몰입감을 얹는다.

| 우리는 이렇다 | 우리는 이렇지 않다 |
|---------------|---------------------|
| 절제된 에디토리얼 (여백·세리프) | 촘촘하고 정보 과밀한 대시보드 |
| 차분한 서가에 딱 하나의 코랄 포인트 | 알록달록한 컬러 남발 |
| 책이라는 물성(物性)을 존중 | 책을 텍스트 목록 행으로 취급 |
| 동네 이웃 같은 친근함 | 익명 중고거래 플랫폼 |

### 1.3 핵심 디자인 원칙

**① 책은 물건이다 (Physicality)**
책을 리스트의 한 줄이 아니라 **서가에 꽂힌 물리적 사물**로 표현한다. 책등(spine), 두께감, 그림자, 책갈피 리본이 이 제품의 정체성이다.

**② 서가는 차분하게, 포인트는 하나만 (Quiet Shelf, One Accent)**
책등 팔레트는 **채도·명도를 근접시켜(Dusty Jewel)** 서가 전체가 눈에 편하게 어우러진다. 시선을 끄는 채도 높은 색은 **코랄 하나뿐**이고, 그것도 행동을 유도하는 곳(CTA·활성 상태)에만 쓴다.

**③ 희미함 = 지금 없는 책, 선명함 = 지금 있는 책 (Ghost in Place)**
빌려준 책은 **자리를 지키되 비어 있게** 보여준다. 색으로 상태를 외치지 않고, 존재감의 농도로 말한다.

**④ 색으로 재촉하지 않는다 (No Alarm Colors)**
반납이 임박해도 **책갈피 색을 빨강으로 바꾸지 않는다.** D-day는 텍스트로만 조용히 알린다. 서가의 평온함이 경고보다 우선한다.

**⑤ 모바일 우선 (Mobile First)**
한 손 조작, 하단 5탭, 44px 이상 터치 타겟, 상세는 **하단 시트**로.

## 2. 컬러 시스템

> HSL CSS 변수가 소스 오브 트루스다. HEX는 참고용.

### 2.1 핵심 팔레트 (Light)

| 역할 | 토큰 | HEX | HSL |
|------|------|-----|-----|
| 배경 (크림) | `--background` | `#F4F1EA` | `42 31% 94%` |
| 본문 텍스트 | `--foreground` | `#1A1813` | `43 16% 9%` |
| 보조 텍스트 | `--muted-foreground` | `#57524A` | `37 8% 32%` |
| **흐린 텍스트 / eyebrow** | `--faint` | `#A39D90` | `41 9% 60%` |
| **포인트 (코랄)** | `--primary` · `--accent` | **`#F26A4B`** | `11.1 86.5% 62.2%` |
| 배지 배경 | `--secondary` | `#E8E1D2` | `41 32% 87%` |
| 이웃 블록 배경 | `--muted` | `#EFE9DB` | `42 38% 90%` |
| 카드 표면 | `--card` | 크림 (bg보다 한 톤 밝게) | `40 45% 97%` |

**코랄(#F26A4B)을 쓰는 곳 — 이 4가지뿐**
1. 주요 CTA (대여 신청 / 구매 문의 / 대기 신청)
2. 활성 필터 칩 (배경 코랄 + 흰 텍스트)
3. 활성 탭 아이콘
4. NEW 배지

> ⚠️ **금지**: `#FFF` / `#000` / 차가운 회색 직접 사용. 모든 중립색은 크림·잉크 계열로 따뜻하게 기운다.

### 2.2 책등 팔레트 — **"Dusty Jewel"**

채도·명도를 근접시켜 서가가 차분히 어우러지도록 설계된 6색.

| # | 이름 | HEX | HSL |
|---|------|-----|-----|
| 1 | Dusty Brick | `#9E524A` | `6 36% 45%` |
| 2 | Dusty Navy | `#4E627B` | `213 22% 39%` |
| 3 | Dusty Moss | `#63795B` | `104 14% 42%` |
| 4 | Dusty Ochre | `#B98C55` | `33 42% 53%` |
| 5 | Dusty Plum | `#7B6A83` | `281 11% 46%` |
| 6 | Dusty Teal | `#4F767A` | `186 21% 39%` |

- **책등 텍스트는 예외 없이 크림 `#F4EDE0`** (`--book-spine-text`). 밝은 스파인에 어두운 텍스트를 섞지 않는다 — 통일감이 우선.
- **색 배정은 결정론적이다.** `spine_color`가 없으면 **제목 해시**로 배정한다(`src/types/book.ts`의 `spineFromTitle`). 랜덤이면 새로고침마다 색이 흔들려서 유저가 "내 빨간 책"으로 기억할 수 없다.

### 2.3 책갈피 리본 — 2종만

| 상태 | 의미 | 리본 그라디언트 | 칩 | 화살표 |
|------|------|-----------------|-----|--------|
| **금색 (lent)** | 내가 **빌려줌** (지금 내 손에 없음) | `#D4A827 → #A87010 → #7A4E08` | `#C68510 → #8F5A05` | `↑` |
| **남색 (borrowed)** | 내가 **빌려옴** (지금 내게 있음) | `#7478B8 → #484B8C → #313468` | `#5658A0 → #383A7E` | `↓` |

- **이름칩은 상시 노출** (hover 시에만 보이면 안 된다). hover 시엔 살짝 상승·확대하는 모션만.
- **반납 임박해도 색을 바꾸지 않는다.** D-day는 리본 안 텍스트(`D-2`, `D-day`, `D+1`)로만 표시.
- 리본 클립: `polygon(0 0, 100% 0, 100% 72%, 50% 100%, 0 72%)`, 상단에서 드리움.

### 2.4 고스트 인 플레이스 (빌려준 책)

| 속성 | 값 |
|------|-----|
| 오버레이 | `rgba(244, 241, 234, 0.6)` (크림 반투명) |
| 제목 | `opacity: 0.5` |
| 아웃라인 | `1px dashed #A89E88`, `outline-offset: -2px` |
| **리본·이름칩** | **선명하게 유지** (오버레이보다 위 z-index) |

> 왜 리본만 선명한가: **"돌아올 자리가 보인다"** 는 안심을 주기 위해서다. 책은 비었지만 누가 가져갔는지는 또렷하다.

유틸리티 클래스 `.book-ghost` (`src/index.css`)로 제공한다.

### 2.5 다크 모드 — "Reading Room"

핸드오프는 라이트 기준이다. 다크는 기존 심야 서재 톤을 유지하되 **포인트를 코랄로 통일**한다.

| 토큰 | 값 |
|------|-----|
| `--background` | `25 25% 10%` (#1F1813) |
| `--foreground` | `38 50% 88%` (#EFE5D2) |
| `--primary` / `--accent` | `11 100% 66%` (#FF7355 — 어둠 위 대비 확보용으로 살짝 밝힘) |
| 책등 · 리본 | 라이트와 **동일 값** 유지 |

## 3. 타이포그래피

| 역할 | 폰트 | 스펙 |
|------|------|------|
| **헤드라인 / 디스플레이** | **Instrument Serif** | `font-weight: 400`, `letter-spacing: -0.02em`. 예: "모두의 책장" 40px |
| **본문 / UI** | **Plus Jakarta Sans** | 400~800 |
| **Eyebrow (오버라인)** | Plus Jakarta Sans | `10px` / `700` / `uppercase` / `letter-spacing: 0.3em` / `--faint`. 예: `VIRTUAL LIBRARY`, `BOOKSHELF` |

```css
h1, h2, .font-display {
  font-family: 'Instrument Serif', 'Noto Serif KR', Georgia, serif;
  font-weight: 400;
  letter-spacing: -0.02em;
}
```

> **한글 대응**: Instrument Serif에는 한글 글리프가 없다. **`Noto Serif KR` 폴백이 반드시 뒤따라야 한다.** 순서를 바꾸지 말 것.
> **규칙**: 세리프는 **크게, 드물게.** 본문에 세리프를 쓰면 가독성과 브랜드 임팩트 모두 잃는다.

## 4. 형태 · 간격 · 그림자

### 4.1 라운드

| 대상 | 값 |
|------|-----|
| **하단 시트** | `26px 26px 0 0` (`--sheet-radius`) |
| 카드 | 12–16px (`--radius: 14px`) |
| 배지 pill | 20px (`rounded-full`) |
| 버튼·칩·검색창 | `rounded-full` |
| **책등** | **2px** (거의 각지게 — 실제 책의 물성) |

### 4.2 그림자

```css
/* 책등 — inset으로 두께를 만든다 */
box-shadow: inset -3px 0 5px rgba(0,0,0,.2), inset 2px 0 2px rgba(255,255,255,.16);
```

> **그림자 철학**: 그림자는 "떠 있음"이 아니라 **"실제 물체가 놓여 있음"** 을 표현한다. 그래서 inset을 적극 쓴다.

### 4.3 서가 (Shelf) — **나무가 아니다**

> v1.0의 **호두나무 판자 서가는 완전히 제거됐다.** 에디토리얼 미니멀에서 서가는 배경이 아니라 **얇은 선** 두 겹으로만 존재한다. 책의 물성은 서가가 아니라 **책등 자체**가 만든다.

```
[ 책들 — height 184px, align-items: flex-end, gap 6px, padding-top 24px ]
[ 잉크 선 — height 2px, #1A1813                                          ]
[ 크림 선반 — height 7px, linear-gradient(#DDD6C4, #EFE9DB)             ]
   box-shadow: 0 5px 9px -4px rgba(90,70,40,.4)
```

컴포넌트: `src/components/EditorialShelf.tsx`

**책등 규격**
| 속성 | 값 |
|------|-----|
| 라운드 | `2px 2px 0 0` — **위만 둥글다** (바닥에 붙어 서 있으므로) |
| 높이 | **책마다 다르다** (74%~99%). 제목 해시로 결정론적 배정 |
| 너비 | `flex-1`, `min 26px` / `max 52px` |
| 제목 | **Instrument Serif 11px**, `writing-mode: vertical-rl`, 크림(`--book-spine-text`) |
| 그림자 | `inset -3px 0 5px rgba(0,0,0,.2), inset 2px 0 2px rgba(255,255,255,.16)` |

**리본 규격**: 높이 `34px`, 너비 `64%` · **이름칩**: `top: -15px`, `8px`, padding `2px 6px`

> 높이를 랜덤이 아니라 **제목 해시**로 정하는 이유는 색과 같다 — 새로고침할 때마다 책 높이가 출렁이면 서가가 살아있는 물건으로 안 보인다.

### 4.4 가상 도서관 비네트

서가 콘텐츠 영역에 은은한 몰입감을 준다. 유틸리티 `.shelf-vignette`.

```css
background: radial-gradient(120% 70% at 50% 40%, transparent 55%, rgba(60,45,25,.12) 100%);
pointer-events: none;
```

## 5. 책 상세 — 하단 시트 (Bottom Sheet)

책등/커버를 탭하면 **하단에서 올라오는 시트**로 상세를 연다. (모달 대화상자가 아니라 시트다.)

**구성 순서**
1. **그랩 핸들** — `38×4px`, `#D3CCBC`
2. **표지 + 제목/저자** — 좌측 커버(2:3), 우측 제목(Instrument Serif 22px) · 저자
3. **상태 배지 줄** — `대여 가능 · N명` / `판매중 · S$X` / `대여중` + 상태(S/A/B) + 대여/판매 pill. 배경 `#E8E1D2`, 텍스트 `#57524A`
4. **빌려주는 이웃 블록** — 배경 `#EFE9DB`, 라운드 12px. 아바타 38px(없으면 스파인색 + 닉네임 첫 글자), eyebrow `빌려주는 이웃`, 닉네임 14px/700. 커뮤니티 있으면 칩(`📚 {name}`) + `chevron-right`
5. **소개** — 13px, `line-height: 1.6`, `#57524A`
6. **액션** — 코랄 풀폭 CTA + 위시(하트) 아웃라인 48px

**인터랙션**: framer-motion 슬라이드업 (spring, `stiffness ~300`, `damping ~28`). 오버레이 탭 또는 아래로 드래그 시 닫힘.

## 6. 컴포넌트 (기존 유지)

`src/index.css`의 `@layer components`에 정의됨. **새 스타일을 만들기 전에 여기부터 확인할 것.**

```css
.btn-hip / .btn-hip-outline   /* 알약형 버튼 (primary는 이제 코랄) */
.glass-card                    /* 반투명 + 블러 카드 */
.nav-bar / .nav-item           /* 하단 5탭 (.active = 코랄) */
.pill / .pill-active           /* 필터 칩 */
.input-search                  /* 알약형 검색 */
.shelf-vignette                /* 가상 도서관 비네트 */
.book-spine                    /* 책등 */
.shelf-vignette                /* 가상 도서관 비네트 (신규) */
.book-ghost                    /* 고스트 인 플레이스 (신규) */
```

**인터랙션 원칙**: hover = 위로 뜬다, active = 제자리로 눌린다 (물리적 피드백).

## 7. 모션

| 애니메이션 | 지속 | 용도 |
|-----------|------|------|
| 하단 시트 | spring (stiffness 300, damping 28) | 상세 팝업 슬라이드업 |
| `book-pop` | 0.4s ease-out | 책을 뽑는 동작 (**시그니처**) |
| `fade-up` | 0.5s ease-out | 콘텐츠 등장 |
| `scale-in` | 0.3s ease-out | 모달·팝오버 |
| 리본 hover | 0.2s | 살짝 상승·확대 |

과한 바운스 금지. "조용한 서가"의 톤을 유지한다.

## 부록 A · 디자인 시스템 점검 (2026-08-19)

기준: `design-for-ai` (visual/checklists · visual/ai-tells · skills/usability).
측정: 실제 렌더 390×844.

### A.1 통과한 것 — 유지할 성질
AI 티 검출(ai-tells.md) Must Pass 4항목 **전부 통과**.
폰트가 Inter/Roboto가 아니고, 청록/보라 그라데이션이 아니고, 미감 방향을 두세 단어로
말할 수 있고("에디토리얼 미니멀 + 가상 도서관"), 똑같은 카드 격자가 아니다.
**서가·책등·나뭇결 선반은 generic system이 내놓지 않는 선택이다. 여기를 건드리지 않는다.**

### A.2 터치 타깃 44px — 완료
`Fitts's law(1954)` · `Apple HIG 44pt` · `WCAG 2.5.5`.
- `.tap-44` 유틸(index.css): **보이는 크기는 그대로 두고 히트박스만** `::after`로 넓힌다.
  아이콘을 44px로 키우면 촘촘한 줄에서 서로 붙어 레이아웃이 깨진다.
  ⚠️ 부모에 `overflow: hidden`이 있으면 잘려서 효과가 없다. 새로 쓸 땐 확인할 것.
- `Button size="icon"` 40→44, `size="default"` 40→44, `Input` 40→44.
- 자리가 넉넉한 것(상태 칩·위시 탭)은 실제 높이를 44로 키웠다.
- 확인 방법: `getBoundingClientRect`에는 히트박스가 안 잡힌다.
  `document.elementFromPoint`로 시각 경계 밖을 찍어봐야 한다(±21px 잡히고 25px에서 빠지면 정상).

### A.3 `--faint` 대비 — 완료
`WCAG 1.4.3`. 라이트 모드에서 **2.39:1 → 4.83:1** (`41 9% 60%` → `41 9% 40%`, #A39D90 → #6F695D).
색조·채도는 그대로 두고 명도만 낮췄다. 다크 모드는 이미 5.01:1로 통과여서 손대지 않았다.
`--faint`는 저자명·권수·날짜 같은 **정보**를 담는다. 장식용이 아니라서 4.5:1이 필요하다.

### A.4 타입 스케일 — 7단으로 수렴 (완료)
25종 · 322곳 → **7종**. `9 · 11 · 13 · 15 · 17 · 22 · 30`
- `13 vs 14`(7%), `14 vs 14.5`(3%)처럼 **구분되지 않는 단계**가 여러 개였다.
  계층을 만들지 못하면서 관리 비용만 냈다(`Ch7`: 최소 25% 차이).
- **9px는 '물성 라벨' 전용이다** — 책등에 얹은 배지, 지도 마커 숫자, 픽셀 UI.
  읽는 텍스트에는 쓰지 않는다. 이 예외가 없으면 책등 라벨이 넘친다.
- 새 텍스트를 쓸 땐 이 7개 중에서 고른다. `text-[14px]` 같은 값을 새로 만들지 않는다.

### A.5 모서리 둥글기 — px로 고정 (완료)
화면에 `13.02 · 13.19 · 15.19px`가 나오던 원인은 **임의값이 아니라
`html { font-size: 108.5% }`**(가독성을 위한 의도된 설정)이었다. rem 기반 radius가 8.5% 커진 것이다.
- 문제는 값 자체가 아니라, **px로 박아둔 모서리(2px 책등, 9px 칩)와 계속 어긋난다**는 점이다.
- 모서리는 글자가 아니라 물리적 형태다 → 글자 설정과 결합을 끊는다.
  `--radius`와 tailwind `borderRadius`를 **현재 렌더되는 값 그대로 px로 굳혔다.**
  겉모습은 바뀌지 않고 결합만 사라진다.

### A.6 남긴 것 — 코랄 버튼 대비
`#F26A4B` 위 흰 글씨 **3.03:1**. 14px 볼드는 WCAG의 '큰 글씨'(18.66px)에 못 들어가
4.5:1이 필요하다. **의도적으로 그대로 둔다** — 브랜드 색이고, 사용자 결정이다.
바꾸려면 (a) 글씨를 먹색으로(8.4:1) (b) 코랄을 `#E03710`로(4.45:1). 둘 다 브랜드가 달라진다.

### A.7 규칙 · 실행 버튼과 선택 상태는 같은 색을 쓰지 않는다
**두 번 어겼다.** 위시리스트 탭(F22)에서 한 번, 등록 폼 선택 버튼(F23)에서 또 한 번.
둘 다 "선택된 것을 코랄로 채운다"였고, 둘 다 바로 옆/아래에 코랄 채움 실행 버튼이 있었다.

- 증상: 어느 게 눌러서 끝내는 버튼인지 구분이 안 된다. 쨍한 색이 반복돼 눈이 아프다.
- 규칙: **코랄 채움은 화면당 하나 — 그 화면을 끝내는 행동에만.**
  선택 상태는 `--primary-soft`(#F1DED4) 면 + 코랄 1px 테두리.
  **강한 색은 선(線)으로 쓰고 면(面)은 조용히 둔다.**
- 예외: 여러 개를 켤 수 있는 항목은 코랄 원형 체크 배지를 붙인다(면이 아니라 점이라 괜찮다).
- 확인 방법: 화면에서 코랄로 채워진 면의 개수를 센다. **2개 이상이면 잘못됐다.**
  ```js
  [...document.querySelectorAll('button,div,span,a')]
    .filter(el => getComputedStyle(el).backgroundColor === 'rgb(242, 106, 75)'
                  && el.getBoundingClientRect().width * el.getBoundingClientRect().height > 40)
  ```
  등록 화면 실측: 고치기 전 코랄 면 다수 → **고친 뒤 1개**(등록 버튼) + 체크 배지 1개.

### A.8 세그먼트 컨트롤은 높이만 44px을 지킨다
서가 상단 상태 필터(전체·대여·나눔·판매)는 한 줄에 네 개를 균등 분배한다.
좁은 폰(360px)에서 각 칩은 **34×44**가 된다.

- 폭까지 44로 키우면 **한 줄에 안 들어간다.** 예전엔 가로 스크롤이었는데,
  그러면 '판매'가 화면 밖에 있어 **있는 줄도 모른다.**
- `tap-44`로 히트박스를 넓히면 **바로 옆 칩과 겹쳐** 어느 쪽이 눌릴지 애매해진다 — 더 나쁘다.
- 그래서 **높이만 44를 지킨다.** iOS Segmented Control도 같다.
- 라벨은 짧게 쓴다: `대여 가능`→`대여`, `판매중`→`판매`. 뜻은 그대로다.
- 감사 스크립트에 예외를 넣었다 — **같은 줄에서 폭이 같은 형제가 3개 이상이고 높이가 44 이상**이면 통과.

### A.9 fixed 탭바 아래에 꽉 채우는 요소 — 패딩을 이중으로 세지 않는다
지도 뷰가 탭바 뒤로 숨고 스크롤해야 보였다. 원인이 두 개였다.

1. 높이가 `clamp(400px, 66vh, 660px)`였다. **66vh는 뷰포트 전체의 66%**라
   상단 헤더·서가 헤더·탭바를 셈에 넣지 않는다. 최소 400px도 작은 폰에서는 그 자체로 넘친다.
   → vh를 버리고 **컨테이너의 화면상 위치와 탭바 높이를 직접 재서** 뺀다.
2. 탭바는 `fixed`라 문서 흐름에 없고, 그 자리는 **`main`의 padding-bottom**이 비워둔다.
   지도를 탭바 위까지 채우면 그 패딩이 지도 **아래에 그대로 남아** 문서가 화면보다 63px 길어졌다.
   → 지도 뷰에서는 **계산된 패딩을 읽어 음수 마진으로 상쇄**한다(하드코딩 금지 — 안전영역이 더해진 값도 맞아야 한다).

확인 방법: 6개 폰 크기에서 `scrollHeight - innerHeight <= 1` 과
`지도 bottom <= 탭바 top` 을 같이 본다.

### A.10 화면에 꼭 맞게 채우는 계산 — 세 값 모두 내용과 무관해야 한다
지도(A.9)에 이어 **서가**도 같은 계산이 필요했다(결과 0건일 때 서가가 화면을 채우게).
같은 실수를 **두 번 더** 했으니 공식을 못 박아둔다.

```
쓸 수 있는 높이 = (탭바 위 경계) − (요소의 top) − (요소 아래에 남는 것)
```

**세 값 모두 그 요소의 높이와 무관해야 한다.** 하나라도 의존하면 되먹임이 생긴다.
실제로 겪은 두 가지 —

| 잘못 쓴 값 | 무슨 일이 벌어졌나 |
|---|---|
| `main`의 아래 빈 공간을 뺐다 | 내용이 줄면 그 빈 공간이 커져 → 서가가 **70px로 쪼그라들었다** |
| `main.bottom`을 아래 경계로 썼다 | main은 내용과 함께 늘어나 경계도 같이 내려가 → **3칸에 고정된 채 화면을 넘었다** |

**아래 경계는 반드시 뷰포트 기준으로 잡는다:** `visualViewport.height − 탭바 높이`.
`main.bottom`이나 스크롤 높이는 쓰지 않는다.

그 밖에
- **`floor`를 쓴다.** `ceil`이면 마지막 칸이 화면을 넘어 스크롤이 생긴다.
- 남는 자투리는 칸들이 나눠 가진다 — 안 그러면 아래에 빈 배경이 남아 "잘린 책장"으로 보인다.
- **자투리 분배에 최소값 클램프를 걸지 않는다.** `rows`가 이미 몫이라 최소 높이는 자동으로
  보장된다. 예전에 `max(120, …)`을 걸었더니 작은 폰에서 총 높이가 밀려 25px 스크롤이 생겼다.
- 프레임은 로딩 중 렌더되지 않는다 → 첫 측정에서 ref가 null이면 조용히 빠진다.
  `requestAnimationFrame` 한 번 더 + `ResizeObserver` + `loading` 의존성을 같이 둔다.
- 확인: 6개 폰 크기에서 `scrollHeight − innerHeight ≤ 1` 과 `요소 bottom ≤ 탭바 top`.

### A.11 안전영역 — 전 화면 규칙과 자동 감사
가상공간의 「나가기」가 아이폰 시계에 가려 안 눌린 데서 시작해, **모든 화면**으로 넓혔다.
가상공간(`/space`)의 「나가기」 버튼이 **아이폰 시계에 가려 눌리지 않았다.**

- 원인: 화면 루트가 `fixed inset-0` 이라 노치 아래까지 그린다. 그런데 위에 얹은 버튼은
  `top-4`(16px) 고정값이라 상태바(약 59pt) 안으로 들어간다.
- ⚠️ **`Index`에만 `safe-top`을 넣어서 놓쳤다.** 전체화면 페이지는 앱 헤더·탭바를 안 쓰므로
  그 규칙이 적용되지 않는다. `fixed inset-0` 을 새로 쓸 때마다 따로 챙긴다.
- 유틸: `.inset-top-safe` / `.inset-bottom-safe` (index.css)
  = `calc(1rem + env(safe-area-inset-*, 0px))`. 웹에서는 env()가 0이라 그대로다.
- 적용: 나가기·방 이름·우상단 버튼 묶음(상단 3개), 채팅 입력줄·말풍선 목록(하단 2개).
- 확인: 스크린샷에서 버튼 상단 y좌표가 상태바 높이(59pt × 배율)보다 아래인지 잰다.
  iPhone 17 실측 — 상태바 경계 177px, 버튼 상단 238px (여유 61px).

#### 규칙
- `env(safe-area-inset-*)` 를 **직접 쓰지 않는다.** `--safe-top` / `--safe-bottom` 변수로 감싼다.
  헤드리스 브라우저에서 `env()` 는 항상 0이라, 변수로 감싸야 **노치를 흉내 내 검증**할 수 있다.
- 유틸(index.css)
  | 클래스 | 쓰는 곳 |
  |---|---|
  | `.header-safe` | 화면 맨 위에 붙는 헤더(전체화면 오버레이 포함) |
  | `.sticky-under-header` | 앱 헤더(3.5rem) 아래에 붙는 sticky |
  | `.inset-top-safe` / `.inset-bottom-safe` | `fixed inset-0` 위에 얹은 버튼 |
  | `.safe-top` / `.safe-bottom` | 컨테이너 패딩 |

#### 적용한 곳
앱 헤더·탭바(Index) · 서가/위시 sticky 헤더 · 약관 · 개인정보 · 관리자 ·
채팅 모달 헤더 · 가상공간 상단 3개(나가기·방 이름·우상단)와 하단 2개(입력줄·말풍선).

#### 자동 감사 — `npm run audit:safearea`
`--safe-*` 변수를 **iPhone 17 값(상단 59 · 하단 34)으로 덮어써** 노치를 흉내 내고,
그 띠 안에 중심이 들어간 인터랙티브 요소를 찾는다. 11개 화면을 돈다.

⚠️ **스크롤로 빼낼 수 있으면 문제로 세지 않는다.** 긴 목록의 중간 항목이 잠깐 그 자리에
있는 것과, 고정 버튼이 영영 가리는 것은 다르다. 처음엔 이걸 구분하지 않아
프로필의 '차단 목록'(스크롤되는 메뉴 행)을 오탐했다.
판정: `position: fixed|sticky` 이거나, 스크롤 가능한 조상이 없을 때만 문제.

⚠️ **화면 '진입'만 도는 감사는 오버레이를 못 본다.** 실제로 가려져 있던 X·저장 버튼은
**가상공간 안의 캐릭터 에디터**였다 — 눌러 들어가야 나오는 화면이라 첫 감사를 통과했다.
지금은 캐릭터 에디터·커뮤니티 상세·게시판까지 **열어서** 확인한다(16개 화면).
**새 전체화면 오버레이를 만들면 감사에도 그 진입을 추가한다.**

약관 · 개인정보 · 관리자. `h-14` 를 쓰면 `box-content` 를 같이 준다 —
