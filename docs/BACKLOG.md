## 🐞 버그 (신뢰·사용성 직결)

### B1 · 레이어 클릭 관통 (P0)
겹친 화면에서 **뒤 레이어의 버튼이 클릭됨**. 예: 캐릭터 저장 버튼을 눌렀는데 뒤에 있던 관리자(NPC)가 클릭됨.
- 원인 가설: 모달/오버레이가 배경 클릭·포인터 이벤트를 막지 않음(Phaser 캔버스는 DOM 오버레이 위에서도 포인터를 받음). 최상단 레이어만 이벤트 받도록 backdrop `pointer-events` 차단 + 캔버스 입력 비활성화 필요.
- 완료 기준: 오버레이가 떠 있는 동안 그 아래(다른 DOM·Phaser 캔버스) 어떤 것도 클릭되지 않는다.

### B2 · 게시판 글 입력 버그 (P0)
입력에 **딜레이 + 일부 문자 누락**. 한글이 제대로 안 들어감.
- 원인 가설: **한글 IME 조합 중 controlled input이 매 키 입력마다 리렌더/상태 갱신되어 조합이 깨짐**(composition break). 또는 Phaser가 keydown을 가로챔. → `compositionstart/end` 처리, Phaser 키 캡처 비활성화(게시판 열릴 때 `this.input.keyboard.enabled=false`), 디바운스 제거/조합 완료 후 반영.
- 완료 기준: 빠르게 타이핑해도 한글/영문 누락·지연 없이 그대로 입력된다.

### B3 · 커뮤니티 멤버 목록 스크롤 안 됨 (P1)
상단(게시판·책장 등 진입 버튼)은 **고정**, 멤버 목록만 **상하 스크롤**되어야 함. 지금 목록 스크롤 불가.
- 완료 기준: 헤더 고정 + 멤버 목록 영역만 `overflow-y-auto`.

### B4 · 게시판에서 새로고침하면 커뮤니티 탭으로 튐 (P1)
게시판 보던 중 새로고침 → 게시판이 아니라 커뮤니티 탭으로 이동. 라우팅/상태 복원 문제.
- 완료 기준: 새로고침해도 보던 위치(게시판)로 복원.

### B5 · 가상룸 "이 책장" 안내 시 책장이 화면 밖 (P1)
관리자 온보딩이 "이 책장을 클릭"이라고 하는데 **책장이 화면에 안 보여** 무엇을 말하는지 모름.
- 해결 방향: 투어 단계에서 **카메라를 대상 가구로 이동/줌** + 하이라이트 화살표. 대상이 뷰포트 안에 들어오도록.

## ⭐ 리뷰·신뢰

### F2 · 책 별점 리뷰 (P1)
책에 대한 **만족도 별점 + 한 줄 리뷰**. 반납 처리 흐름에서 자연스럽게 물어보면 좋음(테스트 중 "별점 필요?!" 반응).
- 노출: 책 상세에 평균 별점 + 리뷰.
- **결정 필요**: 척도(5점?), 입력 시점(반납 완료 시 팝업 vs 상시), 리뷰 공개 범위.

### F3 · 거래 상대 유저 리뷰 (익명) (P2)
활동 뱃지는 오래 쓴 사람은 다 받고 **긍정 일색**이라 이상 이용자를 못 거른다(인터뷰 핵심 지적).
- 스펙: **익명**으로 남기고, **본인은 자기 리뷰를 못 봄**, 다른 유저에게만 노출.
- 참고: "당근 온도" 같은 지표는 굳이 필요 없다는 의견 → 별점보다는 신뢰 신호(거래 완료 수 + 익명 리뷰) 조합 검토.
- **결정 필요**: 완전 익명 vs 거래 기반 인증 리뷰(실제 거래한 사람만), 악용(보복 리뷰) 방지, 최소 표시 기준.

## 📥 위시리스트

### F4 · 위시리스트 검색창 제거 (P1)
상단 메인에 검색창이 있어 **책 추가하려다 검색창을 먼저 누르는 오인**이 잦음. 위시리스트는 "원하는 책을 올리기만" 하면 되므로 상단 검색은 제거하고 **책 추가**를 메인으로.
- (내 위시 목록 검색이 꼭 필요하면 부차적 위치로.)

### F5 · 위시리스트 정렬/필터 (P2)
지금 정렬 기준 없음. 아이디어(택1 이상):
- **내 거주 권역 근처 유저의 요청 우선**(회원가입 region 활용) ← 인터뷰 요청
- **내가 도와줄 수 있는 요청 우선**: 내가 보유/등록한 책과 제목 매칭되는 위시를 상단에("내가 줄 수 있어요")
- **같은 커뮤니티 멤버**의 요청 우선
- **여러 명이 원하는 인기 책** 우선
- **desired_mode 필터**(대여 원함 / 구입 원함) — 이미 데이터 있음, 필터 UI만
- 오래 못 구한(오래된) 요청 돕기 / 최신순 토글

### F6 · 위시리스트 "가지고 있어요" 메시지 흐름 정비 (P1)
지금은 메시지 버튼 → **본인도 모르게 자동 발송**되어 당황(인터뷰: "나도 모르는 사이에 문의가 들어감").
- 흐름: 버튼 클릭 → **확인 안내 팝업**("○○님에게 이 책을 가지고 있다고 알릴까요?") + **실제 발송될 내용 미리보기** → 확인 시 **요약 카드 전송**(위시 책 정보 요약 + "이 책을 보유 중이에요" 알림, 대여 요청 카드처럼) → **해당 채팅으로 이동** → 이후 자유 대화.
- 참고 버그: 예전엔 발송 후 채팅창으로 이동 안 되던 오류도 있었음(같이 확인).

## 🗺 위치·지도

### F10 · 지도뷰 + 위치 기준을 MRT역으로 (구현됨, 미배포)
책 위치를 "거주 지역(planning area)"이 아니라 **집에서 가까운 MRT역**으로 잡고, 서가 탭에 지도 보기를 추가.
- **왜 역인가**: 지역은 몇 km라 지도에서 거리 감각이 안 나오고, 정확한 주소는 남의 집 위치를 공개하는 것이라 못 쓴다. 역은 그 중간 — 공공장소이고 실제 만나서 주고받는 지점이다.
- **왜 핀이 아니라 버블인가**: 책마다 핀을 찍으면 지도가 곧 주소록이 된다(한 사람이 10권 올리면 그 집 위에 핀 10개). 역 단위 버블은 반대로 책이 모일수록 버블만 커지고 개인은 흐려진다.
- 구현: `src/data/mrtStations.ts`(109개역) · `MrtStationPicker` · `BookMapView` · 서가 탭 3분할(책등·표지·지도) · 마이그 `20260811000001`(profiles.mrt_station + GRANT + profiles_public 뷰 + handle_new_user).
- 같이 고친 버그: `transformDbBook`이 owner.district를 안 넘겨 **지역 필터가 아무 책도 못 거르고 있었음**.
- **남은 것**: 기존 유저는 mrt_station이 전부 NULL이라 지도가 빈 상태다. 프로필에서 역을 설정하도록 유도하는 안내(1회 배너 등)가 필요.
- **다음 후보**: 역별 추천 만남 장소(공공장소 1~2곳), 노출 범위 설정(역/권역/숨김/커뮤니티만).
- 지도 = Leaflet + **CARTO Positron**(라이트) / **Dark Matter**(다크) + **직접 그린 MRT역 레이어**.
  - 타일 후보 8종을 실제 렌더해 비교(A~H) 후 **G안 채택**. Positron/Voyager/OSM/Esri 모두 검토.
  - 타일에 역 표시를 맡기지 않는 이유: ①Voyager는 라이트에만 역이 있고 **다크판이 없어** 테마 바꾸면 역이 사라짐 ②어느 줌에 어떤 역을 보일지 통제 불가 ③타일 제공자 교체 시 역 표시도 같이 날아감.
  - 역 레이어 규칙(구현됨): 줌 <12 미표시 · 12 점만 · 13+ 점+이름 · **책이 있는 역은 책 마커가 대신**(중복 라벨 방지) · 뷰포트 안만 렌더.
  - 드래그·핀치 줌, 마커 클릭 시 그 역의 책 목록 팝업(표지·제목·저자, 클릭 시 상세).
  - ⚠️ CARTO 무료 타일은 대량 트래픽 시 정책 위반 → 유저 늘면 타일 URL 교체(`BookMapView.tsx`의 `TILES` 한 줄). 역 레이어는 우리 데이터라 영향 없음.

## 🛡 운영·관리자

### F12 · 관리자 탭에서 책 숨기기 (P1)
관리자가 특정 책을 서가·검색·지도에서 **안 보이게** 할 수 있어야 한다. 지금은 신고를 받아도 관리자가 손쓸 방법이 없다(삭제는 책 주인만 가능).
- 스펙: `books.hidden_by_admin`(bool) + 숨긴 사유·시각·관리자 id. 조회 쿼리 전반에서 제외하되 **주인 본인에게는 보이게** 하고 "관리자에 의해 숨겨졌어요" 안내.
- 진입: AdminPortal에 책 목록(검색·신고건수 정렬) → 숨기기/해제 토글. 신고 화면에서 바로 숨기기도 가능하면 좋다.
- 하드 삭제가 아니라 숨김인 이유: 오판이었을 때 되돌릴 수 있어야 하고, 거래 이력이 걸린 책은 지우면 대화·거래 기록이 깨진다.
- **결정 필요**: 숨겼을 때 주인에게 알림을 보낼지(보내면 이의제기 경로도 필요), 진행 중인 거래가 있는 책도 숨길 수 있게 할지.

## 📱 네이티브 앱 (iOS · Android 스토어 출시)

### F11 · 앱스토어 출시 (계획 확정, 백로그 추가 이후 착수)
현재는 웹앱(PWA)뿐. iOS App Store · Google Play에 올릴 앱으로 만든다.

- **방식**: **Capacitor** 권장. 지금 코드(Vite + React + Phaser)를 그대로 네이티브 셸에 담는다. React Native는 전면 재작성이라 해당 없음.
- ⚠️ **가장 큰 리스크 — Apple 심사 가이드라인 4.2(Minimum Functionality)**: 웹사이트를 그대로 감싼 앱은 반려된다. 네이티브다운 기능이 필요하다. 모아북에 자연스러운 후보: **네이티브 푸시**, **카메라로 책 표지 촬영**, **공유 시트**, **생체인증 로그인**, 오프라인 서가.
- ⚠️ **푸시를 새로 깔아야 한다**: 지금은 Web Push(VAPID) + 서비스워커 + `send-push` 엣지 함수다. 네이티브는 **APNs(iOS)/FCM(Android)** 토큰이라 `push_subscriptions`에 토큰 종류 구분을 추가하고 발송 함수가 두 채널을 타게 해야 한다. **이 작업이 제일 크다.**
- ⚠️ **서비스워커가 웹뷰에서 불안정**: 현재 PWA 흰화면 방지·청크 복구 로직은 앱에서 다르게 가야 한다.
- **딥링크**: 이메일 인증·알림 링크가 `/auth` 등 웹 경로 기준 → Universal Links(iOS)/App Links(Android) 설정 필요.
- **비용**: Apple Developer $99/년, Google Play $25(1회).
- ✅ **이미 갖춘 심사 요건**: 계정 삭제(delete-account 엣지함수), 신고·차단(UGC 앱은 Apple 1.2에서 필수), 이용약관·개인정보 링크. 이 셋이 없어서 반려되는 경우가 흔한데 모아북은 이미 있다.
- **버전 스큐**: 웹은 즉시 배포, 앱은 심사 대기 → 두 채널 버전이 갈린다. 강제 업데이트 안내 화면이 필요할 수 있음.
- **점검 필요**: Phaser 가상공간이 구형 아이폰 WKWebView에서 메모리·프레임 버티는지.
- 📌 **이전 결정을 뒤집는 항목**: 2026-08-02에 "네이티브앱은 PMF 검증 후 검토, PWA+텔레그램으로 iOS 마찰 우회"로 정했었다. 이제 출시 예정으로 승격.

## 🔧 인터뷰에서 추가로 뽑은 항목 (내 제안)

### A1 · 모든 화면에 일관된 뒤로가기 (P1)
인터뷰: "뒤로가기 버튼이 모든 페이지에 다 있어야 됨". 온보딩·상세·설정 등에서 되돌아갈 경로 일관화(특히 게시판·가상룸·모달).

### A2 · 위시리스트 대여/구입 요청 구분 표시·검색 (P2)
인터뷰: "대여 요청/구매 요청으로 구분해서 검색". desired_mode 배지는 있으나 필터·구분 탐색은 없음 → F5와 함께.

### A3 · 회원가입 이메일 한도 (모니터링)
테스트에서 "이메일 많이 보내서 안 감" → **Custom SMTP + Rate Limit 상향으로 해결됨**. 발송 안정성 모니터링만 유지.

### A4 · 콜드스타트(공급) 전략 (P1, 사업)
NPS 8이지만 "사용자·책이 충분해야 경쟁력". "장르 불문 다다익선, 어떤 책이든 있다는 인식"이 사용 동기 → 초기 책 시딩/위시 매칭이 핵심. (제품 아닌 운영 백로그)

### A5 · 반납 시 별점 유도 (F2 연계)
반납 완료 액션 직후 별점/리뷰 팝업을 붙이면 리뷰 수집률↑ (테스트에서 자연스럽게 기대함).

---

## ✅ 결정됨 (2026-08-05)
1. **리뷰 구조**: 책 리뷰=**공개**(별점 1~5 + 한 줄), 책 상세의 설명 아래에 평균+목록, 입력은 **반납 완료 직후 팝업**(+상시). 유저 리뷰=**익명**(별점 1~5 + 한 줄), 상대 프로필에 평균+익명 목록, **본인은 자기 리뷰 섹션을 못 봄**. 활동 뱃지와 별개(뱃지=긍정 참여, 리뷰=신뢰 신호).
2. **위시 정렬 기본값(F5)**: **거주 권역 근처 + "내가 줄 수 있는 책"(내 보유와 제목 매칭) 우선** 조합.
3. **F6 카드**: 책 제목 / 판형(있으면) + 요청자 한마디 + "이 책을 보유 중이에요" 문구. 확인 팝업에 실제 발송 내용 미리보기 → 확인 시 카드 전송 + 채팅 이동.
4. **F8** = 가상룸 관리자(NPC) 기능 확장 → **P3 보류**(가상룸 사용 동기 낮음, 버그만 우선).

## ❓ 남은 결정
1. **보증금(F9)** — 합의·안내형(경량) vs 실제 에스크로. (베타 권장: 경량)
2. **네이티브 앱(F11)** — Apple 4.2를 통과할 **네이티브 기능을 무엇으로 채울지**. 푸시만으로는 약할 수 있어 카메라 촬영·공유 시트 중 최소 하나는 붙이는 게 안전하다.
3. **네이티브 앱 시점** — 웹 백로그(F2~F7)를 끝내고 갈지, 병행할지. 푸시 재작업이 커서 병행하면 양쪽 다 느려진다.

## 🛠 작업 순서(확정)
**B1·B2(P0) → B3·B4·B5·F6** 순으로 진행 → (완료) → **F10 지도뷰**(구현·미배포) → 웹 백로그(F2·F4·A1) → **F11 네이티브 앱**.
